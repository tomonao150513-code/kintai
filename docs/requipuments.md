# タスク別勤怠システム 要件定義書

- 文書バージョン: 0.2
- 作成日: 2026-09-07
- 更新日: 2026-09-07（§10 未決事項に回答、全項目確定）
- ステータス: 合意済み（P0 実装着手可）

---

## 1. 目的・背景

タスク（作業内容）ごとに「いつ・どのタスクを・どれだけの時間」作業したかを
打刻ベースで記録し、実働時間を集計・可視化・エクスポートできるシステムを構築する。

- 当面は**自分ひとり専用**の勤怠記録ツールとして運用する。
- 将来的に**チーム（複数人）対応**へ拡張できるようにデータモデルを設計する。

---

## 2. 用語定義

| 用語 | 意味 |
| --- | --- |
| プロジェクト (Project) | タスクをまとめる上位の分類単位。例: 「社内システム開発」「顧客A案件」 |
| タスク (Task) | プロジェクトに属する具体的な作業単位。例: 「ログイン画面実装」 |
| 打刻 | タスクに対する「開始」「終了」の操作 |
| 勤怠記録 / タイムエントリ (TimeEntry) | 1回の「開始〜終了」で生成される作業時間レコード |
| 実行中タイマー | 終了がまだ打刻されていない勤怠記録（現在作業中の状態） |
| 実働時間 | 終了時刻 − 開始時刻。休憩控除は当面なし |

---

## 3. スコープ

### 3.1 対象範囲（この開発で作るもの）

- ログイン認証（単一ユーザー、Django標準認証）
- プロジェクトの登録・編集・アーカイブ
- タスクの登録・編集・アーカイブ（プロジェクトに紐付け）
- 開始 / 終了ボタンによる打刻
- 勤怠記録の一覧表示・手修正・削除
- 期間 / プロジェクト / タスク別の集計とグラフ表示
- 勤怠実績の CSV / Excel エクスポート

### 3.2 非スコープ（今回は作らない）

- 給与計算・残業代計算・法定帳票
- 承認ワークフロー（上長承認など）
- 打刻の位置情報・IP制限・不正打刻検知
- スマホネイティブアプリ
- 他システム連携（会計・プロジェクト管理ツール等）
- 複数ユーザーの権限管理（※将来拡張として設計のみ考慮）

### 3.3 将来対応（今回は作らないが、設計時に拡張余地を残す）

- **休憩時間の控除**（実働時間 = 経過時間 − 休憩時間）。
  今回は実装しないが、`TimeEntry` に休憩分を後から加えられる構造を意識して設計する（§7.1 参照）。
- チーム（複数ユーザー）対応（§11 P7、付録参照）。

## 4. 利用者・ロール

| ロール | 当面 | 将来（チーム対応時） |
| --- | --- | --- |
| 一般ユーザー | 本人のみ。自分の記録を作成・編集・集計・出力 | 各メンバーが自分の記録を操作 |
| 管理者 | 一般ユーザーと兼務（Django管理画面を利用） | 全メンバーの記録閲覧・集計・エクスポート、プロジェクト管理 |

> 設計方針: すべての `TimeEntry` / `Project` は作成者（`user` / `owner`）を最初から保持し、
> 一覧・集計は「ログインユーザーで絞り込み」を基本とする。将来はこの絞り込みを外すだけで
> チーム集計に拡張できるようにする。

## 5. 機能要件

### 5.1 認証 (F-AUTH)

| ID | 要件 |
| --- | --- |
| F-AUTH-01 | ユーザーはID/パスワードでログインできる |
| F-AUTH-02 | 未ログイン時、勤怠関連の全画面はログイン画面へリダイレクトする |
| F-AUTH-03 | ログアウトできる |
| F-AUTH-04 | 初期ユーザーは `createsuperuser` で作成する |

### 5.2 プロジェクト管理 (F-PRJ)

| ID | 要件 |
| --- | --- |
| F-PRJ-01 | プロジェクトを新規作成できる（名称・説明・表示色） |
| F-PRJ-02 | プロジェクトを編集できる |
| F-PRJ-03 | プロジェクトをアーカイブ / アーカイブ解除できる（削除はしない） |
| F-PRJ-04 | アーカイブ済みプロジェクトは打刻対象の選択肢に出さない |
| F-PRJ-05 | プロジェクト一覧を表示できる（アクティブ / アーカイブでフィルタ） |
| F-PRJ-06 | 記録が1件以上あるプロジェクトは物理削除不可（アーカイブのみ） |

### 5.3 タスク管理 (F-TSK)

| ID | 要件 |
| --- | --- |
| F-TSK-01 | タスクをプロジェクトに紐付けて新規作成できる（名称・説明・状態） |
| F-TSK-02 | タスクの状態を管理できる（未着手 / 進行中 / 完了） |
| F-TSK-03 | タスクを編集・アーカイブできる |
| F-TSK-04 | プロジェクトを指定してタスク一覧を表示できる（状態でフィルタ） |
| F-TSK-05 | アーカイブ済み・完了タスクは打刻対象の既定選択肢から除外できる |

### 5.4 打刻 / 勤怠記録 (F-PUNCH)

| ID | 要件 |
| --- | --- |
| F-PUNCH-01 | タスクを選択して「開始」を押すと、開始時刻を記録した実行中タイマーを生成する |
| F-PUNCH-02 | 実行中タイマーがあるとき「終了」を押すと終了時刻を記録し、実働時間を確定する |
| F-PUNCH-03 | 実行中タイマーは**1ユーザーにつき同時に1件まで**とする |
| F-PUNCH-04 | 実行中タイマーがある状態で別タスクの「開始」を押した場合、**確認ダイアログを表示**し、承認されたら現在のタイマーを自動終了してから新規開始する（切り替え）。キャンセル時は何もしない |
| F-PUNCH-05 | ダッシュボードで実行中タイマー（対象タスク・経過時間）を常時表示する |
| F-PUNCH-06 | 勤怠記録に任意のメモを付けられる |
| F-PUNCH-07 | 勤怠記録の開始 / 終了時刻・タスク・メモを後から手修正できる |
| F-PUNCH-08 | 勤怠記録を削除できる（確認あり） |
| F-PUNCH-09 | 開始時刻を過去日時に指定した手動追加ができる（打刻し忘れ対応） |
| F-PUNCH-10 | 終了時刻 < 開始時刻、時間帯の重複はバリデーションエラーとする |
| F-PUNCH-11 | 日をまたぐ記録を許可する。集計は**開始日基準で全時間を計上**する（§7.2 案A） |
| F-PUNCH-12 | 実働時間の丸めは行わない（秒単位で保持・表示） |
| F-PUNCH-13 | 「終了」打刻の直後に、確定した実働時間を「時間・分・秒」でねぎらい文言とともに表示する 例:「お疲れ様でした！ 1時間30分24秒 作業しました！」 |

### 5.5 一覧・検索 (F-LIST)

| ID | 要件 |
| --- | --- |
| F-LIST-01 | 勤怠記録を期間（開始日〜終了日）で絞り込んで一覧表示できる |
| F-LIST-02 | プロジェクト / タスク / 状態で絞り込める |
| F-LIST-03 | 一覧は日付降順、1画面あたりの件数はページネーションする |
| F-LIST-04 | 一覧に各記録の実働時間と、絞り込み結果の合計時間を表示する |

### 5.6 集計・ダッシュボード (F-AGG)

| ID | 要件 |
| --- | --- |
| F-AGG-01 | 日次 / 週次 / 月次の合計実働時間を表示できる |
| F-AGG-02 | 指定期間のプロジェクト別・タスク別の内訳（時間と割合）を表示できる |
| F-AGG-03 | 期間内の日別稼働時間を**棒グラフ**で表示できる |
| F-AGG-04 | プロジェクト別（またはタスク別）構成比を**円グラフ / 積み上げ棒グラフ**で表示できる |
| F-AGG-05 | ダッシュボードに「今日の合計」「今週の合計」「実行中タイマー」を表示する |
| F-AGG-06 | グラフ描画データはJSONを返すエンドポイント経由でフロント（Chart.js）が描画する |

### 5.7 エクスポート (F-EXP)

| ID | 要件 |
| --- | --- |
| F-EXP-01 | 期間・プロジェクト・タスクを指定して勤怠実績を CSV でダウンロードできる |
| F-EXP-02 | 同条件で Excel (.xlsx) でもダウンロードできる |
| F-EXP-03 | 出力列: 日付 / 開始時刻 / 終了時刻 / 実働秒数 / 実働時間(HH:MM:SS) / 実働時間(h,小数) / プロジェクト / タスク / タスク状態 / メモ |
| F-EXP-04 | CSVの文字コードは Excel で文字化けしない形式（UTF-8 BOM 付き）とする |
| F-EXP-05 | Excel出力にはシート末尾に合計行、または集計シートを付与する |
| F-EXP-06 | ファイル名に出力条件（期間）を含める 例: `kintai_2026-09-01_2026-09-30.xlsx` |

### 5.8 時間の表示ルール (F-FMT)

| ID | 要件 |
| --- | --- |
| F-FMT-01 | 画面上の実働時間・合計時間は「◯時間◯分◯秒」形式で表示する（例: `1時間30分24秒`、`0時間5分0秒` は `5分0秒` のように上位ゼロは省略可） |
| F-FMT-02 | 秒は切り捨て・丸めを行わず、`end_at - start_at` の実値をそのまま表示する |
| F-FMT-03 | CSV / Excel の「実働時間」列は集計しやすいよう **秒数** と **HH:MM:SS 文字列** の両方を出力する（時間(h)の小数列は補助的に併記可） |
| F-FMT-04 | 日時の表示は JST、`YYYY-MM-DD HH:MM:SS` を基本形式とする |

## 7. データモデル（案）

> Djangoの `django.contrib.auth.models.User` をそのまま利用（将来 `AUTH_USER_MODEL` 差し替えに備え、
> 参照は `settings.AUTH_USER_MODEL` 経由で行う）。

### 7.1 エンティティ

**Project**

| フィールド | 型 | 説明 |
| --- | --- | --- |
| id | PK | |
| owner | FK(User) | 作成者。将来のチーム対応で絞り込みキー |
| name | CharField(100) | プロジェクト名 |
| description | TextField(blank) | 説明 |
| color | CharField(7) | 表示色（`#RRGGBB`）グラフ用 |
| is_archived | BooleanField(default=False) | アーカイブ状態 |
| created_at / updated_at | DateTimeField | 監査用 |

制約: `(owner, name)` はユニーク

**Task**

| フィールド | 型 | 説明 |
| --- | --- | --- |
| id | PK | |
| project | FK(Project, on_delete=PROTECT) | 所属プロジェクト |
| name | CharField(150) | タスク名 |
| description | TextField(blank) | 説明 |
| status | CharField(choices) | `todo` / `doing` / `done` |
| is_archived | BooleanField(default=False) | アーカイブ状態 |
| created_at / updated_at | DateTimeField | 監査用 |

制約: `(project, name)` はユニーク

**TimeEntry（勤怠記録）**

| フィールド | 型 | 説明 |
| --- | --- | --- |
| id | PK | |
| user | FK(User, on_delete=PROTECT) | 記録者 |
| task | FK(Task, on_delete=PROTECT) | 対象タスク |
| start_at | DateTimeField | 開始時刻 |
| end_at | DateTimeField(null=True, blank=True) | 終了時刻。NULL = 実行中 |
| note | TextField(blank) | メモ |
| source | CharField(choices) | `timer`（打刻）/ `manual`（手動追加・修正） |
| created_at / updated_at | DateTimeField | 監査用 |

派生値（DB非保持、プロパティ / アノテーションで算出）:
- `duration` = `end_at - start_at`（`end_at` が NULL なら「現在時刻 − start_at」）。丸めなし・秒単位
- `duration_seconds` / `HH:MM:SS 文字列` … 表示・エクスポート用（F-FMT）
- `work_date` = `start_at` のJST日付（集計の基準日）

制約・バリデーション:
- 部分ユニーク制約: `user` ごとに `end_at IS NULL` は最大1件（`UniqueConstraint` + `condition`）
- `end_at` があるとき `end_at > start_at`
- 同一 `user` 内で `[start_at, end_at)` 区間が他レコードと重複しないこと（アプリ層で検証）

**将来対応（休憩控除・§3.3）のための拡張余地**:
- `TimeEntry` に `break_seconds`（休憩秒数、default 0）を後日追加し、
  `duration = (end_at - start_at) - break_seconds` に切り替えられる構造にしておく。
- または休憩を別テーブル `Break(time_entry, start_at, end_at)` として持たせる案も検討可能。
  今回は**フィールド追加・テーブル追加のどちらでも移行できるよう、実働時間の算出を1箇所（services 層）に集約**する。

### 7.2 集計時の日跨ぎ方針【確定: 案A】

- `start_at` のJST日付にその記録の**全時間を計上**する（F-PUNCH-11）。
- 日付境界での按分（案B）は行わない。必要になれば後日追加する。

### 7.3 ER図

```
User 1 ──< Project 1 ──< Task 1 ──< TimeEntry >── 1 User
                                   (user = 記録者)
```

## 付録: チーム対応（将来）で見込む変更点

- `TimeEntry` / `Project` の一覧・集計クエリから「ログインユーザー絞り込み」を外し、
  管理者は全件、一般は自分のみ、という分岐に置き換える。
